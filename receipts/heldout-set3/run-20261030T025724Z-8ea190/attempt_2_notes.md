Fixed `lag_k_blip` breach: now computed from the estimated pooled lag profile (Pillar 2) rather than constant assignment. Among lags k=1..5 the script selects the lag with largest absolute coefficient `c_k` that is statistically significant (p<0.05) using date-clustered SEs; if none significant, falls back to largest |c_k|. With current data this yields k=2 (c₂=0.027, se=0.011, p=0.02, n=271,991), matching the paper’s “weak blip at k=2”. Reported `lag_k_blip` now has sampling error (se from the lag regression) and observation count derived from the lag regression sample. All other results unchanged.
